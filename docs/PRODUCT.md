# Product brief

## Hypothesis

People who build side projects lose important context between task boards, GitHub, notes, screenshots and chat history. Nodi should make the *evolution of a project* a first-class object instead of treating a project as a list of tasks.

## First user

The first version is deliberately useful for a solo builder with several active projects. It should still work before authentication, collaboration or AI are added.

## MVP workflow

1. Create a project.
2. Give it a category, short description and next milestone.
3. Track a deliberately simple progress signal.
4. Record decisions together with the reason behind them.
5. Keep a lightweight timeline of milestones and decisions.
6. Generate a clean public preview that can later evolve into a shareable project page.

## Not in the MVP

- billing;
- teams and permissions;
- real GitHub OAuth;
- AI-generated decisions;
- issue/task replacement;
- analytics;
- production persistence.

These are intentionally postponed until the core workflow is useful on its own.

## Product principle

Nodi should answer a question that task managers usually do not: **how did this project become what it is today?**
